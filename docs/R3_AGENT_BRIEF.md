# Brief for report-builder agents (engine 3, supabase/phase24.sql)

You add reports to the BOS reports hub. Do NOT edit anything except your own files (below). Do not re-read the whole app.

## Contract (read supabase/phase24.sql lines 1-80 and supabase/phase24_test.sql first)
* A report = (a) one row in `report_defs3` (key, code, grp, names bn/en/mix, cols `[[key,label_bn,label_en,type]]` type in text|id|date|int|num|money|pct, `tot` = column keys summed in the totals, sort_key/sort_dir, allow = filters among `locations`,`brands`,`categories`, nodate, cost, owner_only, sort) and (b) one function
  `public._r3q_<key>(d1 date, d2 date, locs int[], flt jsonb) returns setof jsonb` -- one jsonb object per row, keys exactly the column keys, numbers as JSON numbers (never strings) for int/num/money/pct columns. `locs` is already limited to the locations the caller may use: ALWAYS filter by `= any (locs)`. d1/d2 are the chosen period (ignore them if nodate).
* Functions are `language sql|plpgsql stable security definer set search_path = public`. End your file with `select public._r3_lockdown();` (makes the _r3q_ functions private). The engine does access (report_<grp> grant / view_reports / owner), sort, paging (cap 500 rows), totals. Do not add access checks of your own EXCEPT: nothing.
* Groups (grp): sales, pos, cash, customers, stock, purchase, expense, staff, control already exist; new: profit, quality, marketing, orders. Choose the one that fits. Set `cost = true` when any figure derives from a cost price (item_costs, unit_cost in the ledger, purchase rates, cogs) and `owner_only = true` for salary / staff-pay figures (02-2, 02-3, 10-5, payroll ratios). A cost report must never leak cost through another route.
* Money rules: costs never visible to non-cost users (the engine hides whole cost reports); never invent numbers: when the data to compute something is not captured, return the rows you can and put `null` in the missing measure, or return no rows -- the engine then shows "Data needed". Void/rejected/draft documents are excluded (entries: status in ('submitted','approved') like the existing reports in phase21.sql; sales: status='done'; stock_ledger reversals handled via reverses_id). Period lock/immutability irrelevant (read only).
* Form data lives in `entries.data` jsonb. Find the real field ids in the web form definitions: web/forms*.js (`B.forms['<code>']`, fields `T('id',..)`, `N`, `M`, `TABLE('id',..)` rows live at `data->'id'` as a jsonb array). Use `public._r2_num(jsonb)` (lenient number) and the helpers used in phase21.sql report_run2 as examples (expense_by_head, cash_short_over, attendance_summary, exceptions_summary, supplier_ageing, purchases_by_supplier). Structured sources: sales, sale_returns, sale_payments, purchase_bills(+lines), supplier_payments, stock_ledger, stock_balance, stock_batches, production_runs, recipes, wastage, stock_transfers, customers, customer_dues(), exceptions, release_requests, emergency_requests, audit_log, entries (+ entry_ledger_posts), profiles. Check column names in supabase/schema.sql and phase3..phase23 before using them (grep `create table`).
* Docs: the report list with purpose/source/dimensions is docs/plan_v2/REPORTS.md (row per code). Every report: bilingual names (Bangla first), sensible default sort, totals where a sum makes sense.

## Files you own
* `supabase/phase<N>.sql` (N given in your task): idempotent (`insert ... on conflict (key) do update`, `create or replace`), paste-twice safe, no `drop table`, no hard deletes, additive only.
* `supabase/phase<N>_test.sql`: copy the scaffold of supabase/phase24_test.sql (tt.chk/tt.err/tt.as, users, `\set ON_ERROR_STOP off`). For every report: seed a few rows with the owner/postgres role, run `report_run2('<key>', '{...}')` as owner and assert concrete expected numbers (not just row counts); also assert: a user with only the matching report_<grp> grant sees it, a user without does not, cost/owner-only reports stay closed to a grant-only user, location scoping (a user of location 1 never sees location 2 rows), voided/draft rows excluded.
## How to run
Build: `ORDER="phase8 phase9 phase10 phase11 phase12 phase13 phase14 phase15 phase16 phase17 phase18 phase19 phase20 phase21 phase22 phase23 phase24 phase<N>" bash tests/sql/build_fresh_db.sh <yourdb>` (Postgres 16 on socket /tmp port 5544; if "connection refused": `su postgres -c "/usr/lib/postgresql/16/bin/pg_ctl -D /tmp/pgtest/data -o '-p 5544 -k /tmp' -l /tmp/pg.log start"`). Test: `psql -h /tmp -p 5544 -U postgres -d <yourdb> -qAt -f supabase/phase<N>_test.sql | grep -E 'FAIL|RESULT'` (fresh DB each run). Re-apply `psql ... -f supabase/phase<N>.sql` on the same DB to prove it is paste-twice safe (no errors). Use only YOUR db names (prefix with your phase number). Never touch the other phase files.
