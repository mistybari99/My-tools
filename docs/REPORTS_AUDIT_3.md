## 1. How this was checked (and its limits)
- Inventory: `web/ia.js` routes, hub engines 1/2/3 (`rpt_def` p9:517, `_r2_def` p21:70, `report_defs3` p24 + rows p25:283, p26:493, p27:244), accounts / day book / dues / payroll / attendance / orders / marketing / audit screens, and every `create or replace function` with cash, bank, ledger, pnl, dues, ageing, payroll, attendance, order, audit, exception or forecast in the name.
- Dry-run chain on test data (verified code A): opening journal 900,000 + stock openings; production; cash, mobile and credit sales; collection 120; voided sale; return 100; supplier bill 400 + payment 50; payroll run 8,000 paid by bank; staff advance 1,000; vouchers + quick expenses; owner top-up/draw; bank deposit; wastage, count, transit loss; cash-short cases; 3 online orders (deliver / late / cancel with advance); 3 attendance days; one 18-1 marketing line; one 20-1 cake order; VAT switched on in the scratch DB only; month-close preview; Balance Check. Result: trial balance balanced, balance sheet difference 0.00, Balance Check green (2 amber: day book vs journal -290, inventory vs GL).
- Verified codes: A = ran in the dry run and the figure was compared; B = code read + a named repo test suite (BUILD-LOG says it passes; not re-run); C = code read only. Not tested: a real phone ("Mob Y*" = phone layout exists, device checklist still open), bank-statement matching with real lines, wallet statements, period lock, live volume. Real data is thin, so an empty result means "nothing in the fixture", not "broken".
- DB `current_date` is UTC; the app uses Asia/Dhaka. Clients must send the Dhaka date (a UTC "today" silently drops today's sales).
- Matching rule applied (owner): by PURPOSE, not by name. A different-name equivalent is marked IMPLEMENTED with its route named (column "Existing route / equivalent"); only reports with no equivalent anywhere go to "build".

## 3. Findings (misleading or "not captured" shown as a number come first)
- F1 P1 totals turn "not captured" into 0. Engine 3 totals use `round(coalesce(sum(..),0),4)` (p24:124). Dry run: L5 rows show `fixed`/`be_sales` null but the totals row shows `0.0000`; L1 `profit` is a number even when `gaps` lists missing expenses/salary/fixed (p27:73-85; Sept row profit -6,000 with expenses null). Owner rule: show "data not captured", never 0.
- F2 P1 management P&L vs financial statement. L1/L3/L4/T4 (p27) are management views (sales - COGS - 10-2 vouchers - salary - fixed cost). Dry run: L1 -6,608 vs journal P&L -7,658. `profit_recon` (p92:314) explains it: vouchers -290 (submitted vs approved), salary +1,000 (02-2 sheet 7,000 vs paid run 8,000), wastage -30, transit -50, bill opex -300, overhead +40. The hub does not label L1 "management view"; `profit_one_number_on` and `report_salary_source` are OFF (owner decision OD-8).
- F3 P1 three expense totals for the same period. Expense report 790 (`expense_by_head` p21, skips quick expenses 420), P&L/day book 1,210, journal 920 (approved only). Switches `report_expense_parity_on` and `expense_count_on` (p93) exist but default OFF; no basis notice on screen.
- F4 P1 hub sales reports are gross of returns. Same 30-day window: hub `sales_summary` net 1,150 vs `biz_daily` 1,050 (return 100 netted). No returns line or notice in the hub sales reports.
- F5 P1 staff reports read paper only. `attendance_summary` (p21:368) sums form 02-1 jsonb; the app's `attendance_days` (p42:127) holds punches/OT. Dry run: 3 structured days, hub report returns `[]` with a note about 02-1. Same split: `t3_payroll` / `salary_report` read 02-2 sheets, not payroll runs (p93 header "NOT DONE"). T4 shows salary 7,000 while the paid run is 8,000.
- F6 P1 orders: disconnected sources. `s10_orders` (p25:20) reads paper forms 20-1/20-6 only: 0 rows while 3 structured `online_orders` exist (p61:36). `online_orders_list` (p61:251) computes balance = subtotal - discount + charge - advance: a delivered order shows 250 owed, a cancelled order shows 70 owed. Advances taken at order time reach `sale_payments` only at delivery (day book / journal / account 2300 silent until then).
- F7 P1 cancelled-order refund leaves no money record. `online_order_cancel` (p61:189) stores `advance_fate`, posts nothing. Dry run: cancelled order with fate=refund: no cash move, no journal line, no day-book line.
- F8 P2 marketing spend never reaches the books. Form 18-1 is read only by `e4_marketing_limit` (p25:226) and `m2_marketing_vs_sales` (p26:383). Dry run: 1,500 spend, no journal row. If the same spend is also typed in 10-2 it double counts; if not, profit is overstated. Posting is an owner decision.
- F9 P2 invented thresholds. `m1_rfm` hard-codes 3 orders / 30 / 60 days (p25:61-71); `d5_lapsed` hides customers silent more than 180 days (p25:55). BUILD-RULES 15: settings, not code.
- F10 P2 `x4_compliance` counts every calendar day as missing (p25:100): dry run 623 of 624 showroom-form-days "missing" on a fresh install (no rollout start date, closed days not excluded).
- F11 P2 reads gated by capture switches. `day_book` raises `daybook_off` for non-owners unless `daybook_enabled` (p23:402); `vat_report` returns `off` until `vat_on` (p53:556); bank import needs `bank_recon_on`; orders need `online_orders_on`. Conflicts with "reports stay open" (section 6).
- F12 P2 "Cash flow statement" is a cash-account movement list (`acct_cash_flow` p40:915): no operating/investing/financing; an opening journal dated in the period shows as a 900,000 "manual" inflow; a bank deposit shows 2,000 in and 2,000 out.
- F13 P2 receivable list vs journal. Hub customer dues ignore `customers.opening_balance` while `open_parties_link` is OFF (p88 header), and journal receivable with no customer (1,000 in the fixture) is in no list: dues 80 vs journal 1,080 (`acct_reconcile` shows it). Needs a "not linked" notice.
- F14 P3 loose ends. `ownerboard.js:152` calls `rpc('balance_sheet')`, which does not exist (widget always empty). `d_recipe_cost_gaps` (p83:650) has no screen. `cash_short_over` (p21:351) reads the 14-1 flag and ignores approved/rejected/void state of `shortage_cash_cases` (p81:60). Hub `report_run` refuses ranges over 365 days (p9:927), blocking lifetime customer value.
- F15 P2 forecasts state assumptions only in part. `biz_outlook` (p4:150) shows trading days and an "enough" flag but no range; `reorder_report` (p60:335) uses settings 30/3/7 days (lookback/lead/cover) without showing data coverage. No festival effect anywhere.
- Day book labels card as bank and 10-2 vouchers as cash (`notes`: card_as_bank, imprest_in_cash) - stated on screen, acceptable.
