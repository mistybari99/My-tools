## What was built (per owner decision)
1. **Approval separation hint** - `grant_separation_hint(user, grant)` (owner only): returns `{suggest, blocking:false, pairs, message_bn, message_en}`; `suggest` only when the person would then hold BOTH the entry and the approve right of a pair (his own grant, or through a role; pairs in table `grant_separation_pairs`: recipe_manage/recipe_approve and cost_bill_entry/cost_rule_approve - bills and allocation rules share one pair). Text = the owner's sentence. Owner as the person: never a suggestion (`reason: owner`), nothing is ever blocked (it is advice; `set_user_grant` is untouched). `grant_separation_report()` lists who holds both sides today. **Where it shows**: the delegation board `web/delegation.js` (the screen that lists every grant, incl. recipe_* and cost_*): after a right is given a yellow notice appears; if the hint call fails the grant still stands. Also the "Rules & duty" tab of the new page (pick person + right, plus the "who holds both" list). `web/settings2.js` access screen only handles a fixed list of 12 grants (no recipe / cost right), so it was not touched.
2. **recipe_approval_required** (off / warn / on): already exists (phase73) and is shown by the generic rules hub `web/rules.js` as a raw select without explanation. Added to `#/costattrib` -> Rules & duty: three buttons with a Bangla sentence on what each does (code read of rules.js + tested in the new web test).
3. **Costing method per place** (off / recipe rate / monthly pool + normal monthly output): already on `#/costing` (`loc_cost_cfg_set`, owner only, tested in costing_test.js step C). Rules & duty has a button that points there. Not rebuilt.
4. **production_requires_recipe**: switch on the same tab with a Bangla consequence text (ON: no hand-typed cost production without a recipe, every cost from a recipe; OFF: typed cost allowed, with yellow warning).
5. **Who enters bills / approves rules**: the owner decides later with grants (`cost_bill_entry`, `cost_rule_approve`, new `cost_attrib_manage`); the hint above appears when granting.
6. **MAIN BUILD - attribution** (all backend, all blank by default):
   - `location_cost_attribution`: place (where the share arises), cost type (blank = all types; a typed row beats the general one), destination `showroom` (that place's own P&L) | `main_centre` | `unallocated`, effective month, active, reason, previous values (`prev_id/prev_dest/prev_effective_from`), who/when. No row = unallocated = today. `cost_attrib_set(...)`: effective month must be this month or later (`effective_in_past` - earlier months never change, no back-dating); changing an existing choice needs a reason; the same-month replacement keeps the old row (inactive, `replaced_by`); closed period refused for non-owner (`lock_check`); client_id idempotent; audit. `cost_attrib_retire(id, reason)` takes back a not-yet-past row (row stays inactive). Rows are never edited or deleted (trigger).
   - `cost_attrib_main` + `cost_attrib_main_set`: which place stands for the "main centre" (effective-dated, may be blank = bucket shown only in the cost view).
   - `branch_cost_view(month, loc)` (read-only, cost right): every showroom/admin share of the month (yearly fees /12) with amount, source, cost type, share place, destination kind + place, `via` (setting / default / reassigned), reason, closed-month flag, totals by destination, `in_pl`. Factory shares are not listed (they are product cost).
   - **P&L**: rule `cost_attrib_in_pl` (switch, default OFF). OFF = `l1_pnl` / `l3_shop_pnl` output identical (jsonb equal, tested). ON = SEPARATE rows (`row_type: cost_share`, label "<place> · খরচ ভাগ: <type>" and "(মূল কেন্দ্র)"), `expenses` = share, `profit` = -share, so the report totals follow; original rows unchanged. Unallocated shares never enter the P&L. A main-centre share enters the P&L of the main-centre place if one is chosen for that month, otherwise only the cost view.
7. **Re-assign** - `cost_share_reassign(share, to_kind location|main_centre|unallocated, to_loc, reason, client)`: owner or grant `cost_attrib_manage` (+ cost right); reason (3+ chars) mandatory; append-only table `cost_share_reassign` (old kind/place, new kind/place, amount snapshot, period, who/when, `locked_override`), update/delete blocked by trigger, audit row; history stays visible. Refused: same destination, a factory share, a bill that still has an unallocated part, an inactive share. **Locked period**: non-owner gets `period_closed`; the owner may, the row is flagged `locked_override` and a yellow exception `cost_share_locked_reassign` is raised. A hand move beats the place setting. `location_cost_cfg` untouched (kept).
   - **cost_bill_creates_payment: NOT built** (see owner decisions).
