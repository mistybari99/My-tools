## What was built (every new rule default = today's behaviour)
1. **Free-cost item flag.** Table item_cost_flags (RLS: readable only with the ITEM_COST view right; no direct write grant; audit trigger). Setter `item_cost_free_set(item, bool, reason, client)` (owner or ITEM_COST enter; reason of 3+ characters when marking; client_id replay returns dup; same value = noop). A marked item is a KNOWN cost of 0 in: production_post (the production_requires_cost=refuse check and the finished-good cost), `_cogs_lines72` (so biz_daily / _p27_pl / l1 / l3 / brand_pnl / partner profit do not call its sales "unknown cost revenue"), `_acct_docs` (no cogs_missing flag for sale, return, wastage, production). Nothing is marked by default; blank or 0 cost stays UNKNOWN (bos72). `cost_unknown_items(loc)` = the cost_missing list (tracked items, cost blank/0, not marked); `item_cost_flags_list()`.
2. **Partner base switch.** Rule partner_base_estimate = warn | refuse (default warn). partner_calculate now always adds an `estimated_base` warning (detail = estimated COGS from the item cost list, refuse flag) when part of the COGS comes from item_costs instead of the stock ledger. With refuse, partner_settlement_save raises `base_estimated` when the deed uses a profit base (gross_profit / net_profit) and no typed manual profit base is given; net-sales deeds are not affected.
3. **packaging_return_mode** none | restore | wastage (default none). sale_return calls `_ret_pack80` after the goods are back: packaging = product_packaging (applies_to sale) x returned base qty, never more than the sale's own sale_pack take-out minus what earlier live returns already settled. restore = stock_ledger row on the return (ref sale_return, cost = the sale's packaging cost), so the journal (Dr packaging) and void_sale_return follow it automatically. wastage = record + yellow exception only (the packaging stays expensed in COGS, stock does not grow). Records in sale_return_packaging80 (quantities only, append-only, RLS with POS view).
4. **Dedicated intake bot.** Role `intake_bot`, form ONLINE_INTAKE (enter only; form_rollout rows added like every form), gate `_oo_gate80` used by online_order_save: a bot with that right may only CREATE an order (never edit/confirm/deliver), plus the module and place checks. It has no POS right at all. `intake_bot_create(user, place)` (owner only): role + place + bot flag in one step; refuses the owner and any user that already holds a POS enter/approve role (bot_has_pos_role); `intake_bot_check(user)`. Old-style bots (flag + POS role, phase76) keep working unchanged.
Re-created functions (latest definition via pg_get_functiondef, only bos80 lines changed, all older tags kept): production_post 7-arg (bos72/73/74), _acct_docs (bos50/52/72/74), _cogs_lines72 (bos72), partner_calculate, partner_settlement_save, sale_return, online_order_save. Grants/privileges unchanged; internal helpers (_cost_free80, _oo_gate80, _ret_pack80) closed to browsers.
5. **Web.** #/s1setup (ia rec in group factory, view_cost right): tab 1 marked items + cost_missing list with "mark cost as zero" (asks reason) / unmark; tab 2 intake-bot setup and check (owner only). The two switches are ordinary rules and show in the switchboard. cost_missing and base_estimated now have words in the production and partner screens. Strings via B.L (bn / en / mix), data-act names s1_tab, s1_free, s1_unfree, s1_botmake, s1_botcheck (unique).

# পড়ে বোঝা
* The free-cost mark is read at report time, not stored on past ledger rows: marking an item changes how its OLD sales/runs are read in reports and posting flags (an already posted journal entry is not re-posted). Unmarking brings the flag back for later reads.
* A production run where ALL ingredients are marked free (amount 0) still shows cost_missing in the posting source (amount 0 is not > 0); not changed (nothing invented). recipe_cost (read only) still treats a blank ingredient cost as unknown; not changed.
* estimated_base appears also in warn mode (a new warning line in partner_calculate output; no number changes). Only COGS from item_costs fallback is considered; "uncosted_sales" logic is untouched.
* Packaging restore uses the sale's recorded packaging cost; a sale without sale_pack rows (packaging_consume_on was not "sale") restores/records nothing.
* The bot flag table intake_bots and intake_bot_set (phase76) are unchanged; `intake_bot_create` is the recommended one-step path. A bot created by it holds NO POS role, so inbox_list / online order list are closed to it by design (it only submits).
* Owner decisions still open: whether to switch partner_base_estimate to refuse and packaging_return_mode to wastage (recommended in the tracker, NOT applied); that is S2 (activation guide).
