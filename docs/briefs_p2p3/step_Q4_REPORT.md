## কী বানানো হয়েছে
1. **Landed GRN picker** (`landed_q4.js`): bill বাছার sheet-এ নিচে "Add from a GRN" box। "Show GRNs" চাপলে form 04-1-এর submitted/approved GRN (RLS দিয়ে `entries`) আসে; টিক দিয়ে "Add the bills of the ticked GRNs" -> প্রতিটির জন্য `landed_resolve_docs([{type:'grn',id}])`; যে bill_id ফেরে সেটা বিদ্যমান bill-তালিকায় টিক হয় (তালিকায় না থাকলে বাছাই-তে যোগ হয়), তারপর স্বাভাবিক Continue। link-না-থাকা GRN-এ `grn_not_linked` বার্তা (3 ভাষায়)। **Multi-bill / per-shipment**: bill বাছার checkbox তালিকা আগে থেকেই বহু-বাছাই করত ও `landed_save` একাধিক bill নেয়; নতুন যা যোগ হলো তা হলো mode অনুযায়ী hint (per_shipment: "একাধিক bill/GRN একসাথে টিক দিন"; per_bill: "একটি landed cost = একটি bill") এবং GRN-কে একই বাছাই-তালিকায় মেশানো। আলাদা lot-আইটেম/লাইন-স্তরের বাছাই বানানো হয়নি (server bill-স্তরে কাজ করে, `shipment_ref` লাগে)।
2. **Production** (`recipes.js` ~286): actual-yield input (`pr_ay`, `p_actual_yield` শুধু > 0 হলে) আছে ও কাজ করে। `cost_missing` শুধু তখন আসে যখন rule `production_requires_cost = refuse` (phase79 bos72); তখন আগের থেকেই 3-ভাষার label toast হতো। নতুন tagged edit: server যে `details` (কোন উপকরণের দাম নেই) পাঠায় তা label-এর পরে বন্ধনীতে দেখানো হয়। সীমা: rule `warn` (default) থাকলে production সফল হয় ও server result-এ cost_missing flag নেই (`{id, allocated_exists}`), তাই sheet-এ দেখানোর মতো কিছু নেই; সেক্ষেত্রে খরচের অপেক্ষা badge / books96 দেখায়।
3. **Badge strip** (`badges107.js`): Home (`#hv_main`) ও Owner board (`#ob_main`)-এর উপরে একটি সারি। 7টি chip: ledger problems (`ledger_problem_count`) -> `ledgerlinks`; cost waiting (`cost_wait_list96.total`) -> `books96`; pending auto-posts (`acct_pending_alert85.old_count`) -> `books85`; unmatched forms (`unmatched_forms.lines_unmatched`) -> `unmatched`; unknown-cost items (`items_with_cost` + `items`, costboard-এর মতো) -> `costunknown`; bills without payment (`bills_without_payment99.rows`) -> `billpay`; inbox new (`inbox_board.new_count`) -> `inbox`। chip দেখায় শুধু যদি (১) ওই screen-এর menu entry (`BOS_NAV.entries()[].ok`, অর্থাৎ owner/ঠিক grant) অনুমতি দেয়, (২) count > 0। অনুমতি-না-থাকা chip-এর RPC ডাকাই হয় না। screen আঁকার পরে lazy load, প্রতি call-এ 2 সেকেন্ড cap, function না থাকলে/refuse/ধীর হলে শুধু ওই chip লুকায়; 60 সেকেন্ড cache। `B.posfail.boardCount()` আসলে কোথাও registered নয় (কেউ ডাকে না), তাই সেটার পথ ধরা হয়নি; বিদ্যমান `.badge`/count ধারণা + `BOS_NAV.entries()` অনুমতি-নিয়ম ব্যবহার করা হয়েছে।
4. **Setup advisor Undo** (`setupundo.js`): phase81-এ restore RPC নেই (শুধু `setup_apply_history`)। তাই History tab-এর প্রতি batch-এ owner-only "Undo this apply" button; sheet-এ প্রতি rule-এর "now -> back to" (null = Default); নিশ্চিত করলে প্রতি rule-এ `set_rule(rule_key, old)` (null হলে আপনার নিজের মান মুছে default), set_rule নিজেই owner-only ও audited। কোনো row আন্দাজে বাদ দেওয়া হয় না (ফোনের rules copy পুরনো হতে পারে)।
