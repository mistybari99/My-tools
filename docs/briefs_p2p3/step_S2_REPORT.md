## What was built (all ADVISORY - nothing blocks any sale, purchase, production, journal or order)
* `setup_recommendations()` - 30 rows: all 24 rules added in phases 72..79 plus 6 related switches (accounting_on, accounting_autopost, reports_net_of_returns, online_orders_on, production_requires_recipe, recipe_waste_required) with recommended value, reason (bn / mix / en), current value, default, range, and a status: `ok`, `recommended`, `owner_chosen`, `info`, `not_installed`.
* Recommended values follow the lead's list: production_requires_cost refuse (only after every ingredient cost is known), recipe_approval_required warn, production_manual_needs_reason on, inbox/web form/online orders on, meta_intake off (phone-impossible connection), autodraft off, pii guard on, pack_warn on, keep_order_price on, self-approve switches off (separation), cost_attrib_in_pl on (after assignment), accounting_on on (only when ready, owner decides when).
* NUMBERS ARE NEVER RECOMMENDED (rate limit, window, silence hours, tries, retry, cost-gap %, yield-gap %): status `info`, the shipped default and the allowed range are shown, the owner types his own value in the Switchboard. captcha, public URL, reserve, production_requires_recipe, recipe_waste_required are also `info` (outside setup or owner's call).
* DATA-DRIVEN: rows live in `setup_rec_defs81` (seeded with ON CONFLICT DO NOTHING). Phase80/S1 adds its rules by plain INSERT into that table (and optional checks into `setup_check_defs81`); a row whose rule does not exist yet shows `not_installed`, no error.
* `setup_recommend_apply(p_client, p_codes, p_overwrite, p_ignore_ready)` - owner only, client_id idempotent (second call with the same id returns the stored answer), goes through set_rule (so value validation and the rules audit trigger apply), plus append-only trail (`setup_apply_batches81` / `setup_apply_lines81`: old value, new value, overwrote) and an audit_log row. Never touches a value the owner already chose; `p_overwrite=true` works only for codes named in `p_codes`. Rows whose readiness is not clean are skipped (`not_ready`) unless `p_ignore_ready=true` ("Apply anyway", owner's choice).
* `setup_readiness([topic])` - before switching on: stock_tracking (tracked items, base unit, opening stock, unit conversions, unknown cost, negative), accounting (start date, chart, mappings, opening entry, documents waiting, posting errors), production (recipes, ingredient lines, yield, approval, unknown ingredient cost, unit conversions, pool/recipe cost method complete), cost_sources (sources, approved rule, showroom assignment), online (channels, public URL, intake user). Counts only: no cost value, no amount (cost secrecy).
* `setup_flow_check()` - "সব ঠিকঠাক বইছে?": documents not yet in the books (dated before today), posting errors, documents waiting for a cost, negative stock, productions with an incomplete cost, pool places with no figures this month, unseen messages from earlier days, silence hours, failed intakes, open online-order flags. A system that is switched off shows `na`.
* `setup_apply_history()` - owner's trail.
* Access: read = owner or a person who may see cost (biz_cost_ok); apply + history = owner only. Tables RLS read-only, no browser writes, anon has nothing, helpers closed. No new age or amount limit is invented ("earlier than today", the rule's own silence hours).
* Web `#/setupadvisor` (web/setupadvisor.js): phone-width cards, 4 tabs (Recommended / Before switching on / Is it all flowing / History), apply per row, apply all, replace-my-value (confirm), apply-anyway (confirm). data-act names all prefixed `sadv_` (no clash found in web/*.js). ia.js rec line:
`rec('setupadvisor', 'settings', ['চালু করার গাইড', 'Setup advisor', 'চালু করার guide'], { icon: 'check', ok: (c) => c.own || c.GF.view_cost === true, ... })`; index.html tag after integrations.js. Existing texts untouched.
