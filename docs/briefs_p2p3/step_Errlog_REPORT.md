# Step Errlog - client error log for a phone-only owner (phase107, branch qa/errlog)

**Why**: the owner cannot open a browser console, so a broken screen told nobody. Now a small anonymised note is saved and the owner reads it on `#/problems`.

## What was built
- `supabase/phase107.sql` (+ `phase107_test.sql`): additive, paste-twice safe, one transaction, guard needs 72..103. Independent of 104/105/106. No existing function is re-created.
  - Tables `client_errors` (+ `client_error_seen107` idempotency keys, `client_error_hits107` hour counter). RLS: no direct insert/update/delete; select only owner or `view_client_errors`.
  - RPCs: `client_error_log(p_client, p_batch)` (definer, batch <= 20, idempotent by p_client+cid, dedupe by fingerprint within 10 min -> `count`, never raises), `client_errors_list(from,to,kind,limit,status)`, `client_errors_summary()` (top 20 fingerprints, 7 days), `client_error_resolve(id, note)` (owner, audited, resolves the whole fingerprint), `client_errors_purge(p_days default 60)` (owner, audited).
  - Rules: `client_errors_on` (switch, **default OFF = today's behaviour; recommended ON** - advisor row says why: a phone has no console, only short notes are stored, no sale/book touched), `client_error_rate_max` (owner-typed, blank = built-in ceiling 200/user/hour; a typed number can only lower it, max 200), `client_errors_keep_days` (blank = keep; a number drives an opportunistic auto-purge). Grant `view_client_errors` in `grant_defs`. Three rows in `setup_rec_defs81` (ON CONFLICT DO NOTHING).
  - Privacy: keys matching `token|key|password|secret|authorization|cookie` stripped at any depth from `extra`; JWT-like strings, Bearer values, e-mails and 8+ digit runs removed from message/stack; route loses query string and ids; caps message 500, stack 2000, ua 200, extra 2 KB, note 1000.
  - Decision: kind `user_report` is accepted even while `client_errors_on` is off (a person pressed Send on purpose); automatic kinds are not.
- `web/errlog.js` (new, loaded right after `entry.js` in index.html): window error + unhandledrejection + `sb.rpc` wrapper (non-business errors only: P0001/23xxx/42501/auth ignored; network failures ignored offline, rpc args never read). Memory queue + localStorage (max 50), flush every 30 s and on visibilitychange/pagehide/online, one attempt per tick with back-off (30 s..10 min), flush uses the original rpc so logging cannot log itself, everything try/catch. Rule is read once per session (B.rule if rules are loaded, else one single-row read) and remembered in localStorage; **rule off => no listeners, no rpc wrapper, no timer, nothing sent**.
- Screens: `#/reportproblem` (everybody; note <= 1000, shows route/build/language/last 5 errors, Send -> `user_report`, queued offline) with a button in the drawer footer bar; `#/problems` (owner; grouped by fingerprint with count, last seen, route, Resolve, open/resolved/all filter, copy-as-text for pasting to Claude). `ia.js`: two recs appended at the END (`reportproblem` for everybody, `problems` owner). data-act prefix `er_`. Three languages (English mode all English).
- Not done / notes: a non-owner holding `view_client_errors` has no menu entry (nav.js GF list is fixed, not edited) and opens `#/problems` by link; no purge button on the page (RPC exists); `app_build` is read from a `?v=` on script tags (index.html has none today, so it shows `dev` until the deploy adds one).
