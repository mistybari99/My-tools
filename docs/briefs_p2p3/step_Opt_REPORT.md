## Decision 1 - does a saved / approved bill create a payment?
Existing bills in this code base: cost bills (`cost_source_bills`, phase75) and purchase bills (`purchase_bills`). There is **no separate "expense bill"**: an expense is already the payment (quick expense / form 10-2), so nothing was built for it.
- Rules (module purchase): `cost_bill_creates_payment` and `purchase_bill_creates_payment` = off (DEFAULT) | ask | auto_cash | auto_bank | auto_by_supplier_default; `bill_void_payment_mode` = void (DEFAULT) | keep_credit; `bill_pay_auto_credit_ok` (switch, off); `bill_pay_large_amount`, `bill_pay_small_cash_max` (numbers the owner types, blank = none, NO number built in).
- ask: after the save the screen shows a non-blocking sheet "Record payment now?" (cash / bank / mobile / other; purchase: cash / bank / mobile / card), amount = what is left, editable, part payment allowed, a suggestion line from `payment_recommendation`, a warning + confirm when the same cost may already exist. Server: `bill_pay_info99`, `bill_pay_record` (idempotent by client id). The list "Bills without payment" (`#/billpay`, `bills_without_payment99`) offers the same sheet at any time.
- auto modes: triggers `cs_bills_pay99` (after a cost bill is inserted) and `purchase_bills_pay99` (when a bill becomes `posted`). A failure NEVER blocks the bill: it leaves a yellow flag and the bill stays in the list. Not paid automatically when: the party has credit terms (supplier `credit_days` > 0 or the owner's credit flag in `bill_pay_defaults99`) unless the owner switches `bill_pay_auto_credit_ok` on; the poster already paid something at posting; the cost looks like an existing 10-2 voucher or quick expense. `auto_by_supplier_default` uses the party's own mode (`bill_pay_default_set99`, owner only) or the mode typed on the cost bill; with none known it behaves like ask.
- Where the money goes (the SAME records the rest of the system counts, so it counts once): purchase bill -> `supplier_payments` with `bill_id` (+ `purchase_bills.paid`), seen by supplier balance, cash book and journal like any payment. Cost bill -> `quick_expenses` (path A of the expense domain): `path_guard('expense')` respected (owner made the form the record -> refused, nothing written), the pending form-10-2 shadow is created, the journal source `quick_expense` is unique by `je_source_uq`, closing the day makes ONE shadow form that posts nothing. Mode "other" on a cost bill is a NOTE ONLY row (not in the cash book / journal; the sheet says so). The cost bill itself never becomes a journal source.
- Void: default `void`: purchase payments are voided with the bill (existing void code), cost-bill payments are voided (the engine posts the reversing entry once the original was posted). `keep_credit`: a purchase payment is un-tied from the bill (supplier credit, balance negative), a cost-bill payment stays an expense. A cost-bill payment that is already inside the day-end form or in a closed period cannot be voided: it is kept with a yellow flag. If the existing rule `purchase_void_payments = keep` is on, the link row says `kept_credit`.
- Immutable: `bill_payments99` is the link ledger (append-only; only active -> void | kept_credit), every row audited; nothing deleted.
- `payment_recommendation(kind, ref)`: ask for credit-term parties (never_auto) and for bills at / above the large amount; auto_cash (auto_bank) for bills at / below the small amount, no credit, party's usual mode cash (bank); otherwise ask; with no number typed: ask, basis `no_numbers`. Reasons in bn / mix / en.
- Rows in `setup_rec_defs81` (8, phase '99'): ask / ask / void / auto-credit false / three number rows with NO value ("you type it") / inbox_pii_mode mask_phone_address / unmask limit (info).
