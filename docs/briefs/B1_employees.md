# Module B1: Employees / staff registration (master data), salary structure, facilities, photo, roles and DEEDS
Phase file: supabase/phase41.sql (+ phase41_test.sql). Web: web/employees.js (+ tests/web/employees_test.js). Regs: docs/regs/employees.md. DB names a41*. Another agent (B2) later builds attendance + payroll on TOP of your tables, so keep the schema clean and documented in the file header (table / column list) - they will read supabase/phase41.sql.
Read docs/briefs/00_RULES.md first.
Owner's words: "Employees / Staff Add and registration. All information which logically needs - salary - other facilities - photo - and major roles need for some extra rules which call Deeds. Build the system nicely organised."
## Interpretation
* Employee = a person who works for the business (may or may not have an app login). `profiles` (login accounts, phase 1) stay as they are; an employee may link to a profile (`profile_id` nullable, unique).
* "Deed" = a role/agreement document with extra rules: what the person agreed to (employment deed): contract terms and special clauses that depend on the person's major role (e.g. cashier: cash-handling limit, security deposit, guarantor; storekeeper: stock responsibility; manager: authority limits).
## What to build
1. **employees**: id, employee_no (auto E-0001.. per sequence, immutable, never reused), full_name_bn, full_name_en, nickname, photo_path (private bucket `photos`), gender, date_of_birth, blood_group, nid_no, mobile (normalised like customers: use public.norm_mobile), email, present_address, permanent_address, emergency_name/relation/mobile, marital_status, education note, joining_date, probation_end, designation (list), department (list), primary_location_id + `employee_locations` (other places they may work), employment_type (permanent|contract|daily|part_time|trainee), status (active|on_leave|resigned|terminated|retired) with `status_date`, `status_reason`, profile_id, device_user_id (fingerprint device id, text, unique per device later), bank_account / mobile_wallet for pay, notes, created_by/at. NO hard delete.
2. **Documents**: `employee_documents(employee_id, kind nid|contract|cv|certificate|guarantor|photo|other, file_path, note, uploaded_by, at, void)`; upload UI reuses the photo upload helper (private bucket, signed URL view).
3. **Pay structure (salary-sensitive: owner or grant `salary_view` only; writes owner or grant `salary_manage`)**: `employee_pay(employee_id, effective_from, pay_basis monthly|daily|hourly, basic numeric, note)` effective-dated versions (append-only; current = latest effective_from <= today), `employee_pay_components(pay_id, kind allowance|deduction, name, amount numeric null, percent_of_basic numeric null, taxable bool, active)` (house rent, medical, transport, food, mobile, tiffin...; deductions like provident fund / insurance), overtime policy per employee (`ot_rule`: none | rate_per_hour amount | multiple_of_hourly (e.g. 1.5, 2.0 on holidays); hours basis 8), festival bonus entitlement (`bonus_rules` jsonb: e.g. [{name:'Eid', months_of_basic: 1, min_service_months: 6}]), leave entitlements per year (`employee_leave_entitlements(employee_id, leave_type, days_per_year)`; leave type list seeded: annual paid, sick paid, casual paid, unpaid, maternity/paternity), other facilities / benefits `employee_benefits(employee_id, kind meal|uniform|accommodation|transport|phone|insurance|other, description, value_per_month numeric null, from_date, to_date)`.
4. **Roles & deeds**: `staff_roles` (code, name_bn, name_en, major bool, description) seeded with common roles (Owner's representative / Manager, Cashier, Salesperson, Storekeeper, Factory in-charge, Head artisan / Karigor, Helper, Delivery, Accountant, Guard, Cleaner). `deed_templates(id, role_code, title_bn/en, clauses jsonb [{no, text_bn, text_en, kind rule|amount|duration|text, value, unit}], version, active)`: owner creates/edits templates (new version on change, old kept). `employee_deeds(id, employee_id, template_id null, role_code, title, clauses jsonb (copied from template then customised per person), start_date, end_date null, probation_days, notice_days, security_deposit numeric null, guarantor_name/mobile/nid null, status draft|active|expired|terminated, signed_at, signed_doc_path, created_by)` immutable once active - a change creates a new revision (`revision_no`, `supersedes_id`). A person has one active deed per role at a time. Expiry warnings (function `deeds_expiring(days)`).
5. **Registration UI** `#/employees`: list with photo avatars, search (name/no/mobile/NID), filters (status, location, role, type) via the collapsed controls, summary counts, ⋮ menu per row (open, edit, add deed, add document, change status, link to login account, copy mobile). **Registration wizard** (steps: Personal -> Job -> Pay & facilities -> Documents & photo -> Deed -> Review) saving a draft at each step (idempotent client id), camera/gallery photo capture, duplicate warnings (same NID / mobile). Profile page `#/employee/<id>` with tabs/sections (Overview, Pay (hidden without salary right), Facilities, Documents, Deeds, History) and print view (ID card style + profile sheet). Deeds screen: templates manager + per-person deed creation with a clause editor (add/remove/reorder clauses) and preview/print.
6. Settings/rules: `employees_module_on` (default ON), `employee_mobile_unique` (ON), lists for designation/department seeded via option_lists if that table exists (see phase15) else inline arrays with owner-editable settings.
## Tests
Numbers & permissions: salary hidden from non-salary users (select returns nothing / functions refuse), effective-dated pay lookup, employee_no sequence immutable, duplicate NID/mobile rules, one active deed per role, deed immutability + revision, location scoping for managers (a manager sees employees of their locations), no hard delete, idempotent create.
