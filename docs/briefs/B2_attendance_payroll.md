# Module B2: Attendance, leave, automatic payroll (salary, overtime, bonus, paid leave, deductions) and FINGERPRINT device integration
Phase file: supabase/phase42.sql (+ phase42_test.sql). Web: web/attendance.js, web/payroll.js (+ tests/web/attendance_test.js, payroll_test.js). Regs: docs/regs/attendance.md. DB names a42*. Needs phase41 (employees master: read supabase/phase41.sql first - tables employees, employee_pay, employee_pay_components, employee_leave_entitlements, employee_benefits, deeds...). Build with ORDER ...phase28 phase41 phase42.
Read docs/briefs/00_RULES.md first.
Owner's words: "Staff attendance system - regular - which can calculate automatic salary - overtime - bonus - paid leave - any other extra option needed. And build system for integration of fingerprint device data."
## What to build
1. **Shifts & roster**: `shifts(id, name_bn/en, start_time, end_time, grace_late_min, grace_early_min, break_min, crosses_midnight bool, min_hours_full_day, min_hours_half_day)`, `employee_shift_assignments(employee_id, shift_id, weekday mask or date range, from, to)` (default shift per location too), weekly off days + `holidays(date, location_id null, name_bn/en, paid bool)`.
2. **Punches** `attendance_punches(id, employee_id null, device_id null, device_user_id text, punched_at timestamptz, direction in|out|unknown, source device|manual|app, raw jsonb, import_batch, unique (device_id, device_user_id, punched_at))` append-only. **Daily summary** `attendance_days(employee_id, day, status present|absent|late|half_day|leave|off|holiday|unpaid, first_in, last_out, worked_minutes, late_minutes, early_leave_minutes, ot_minutes, shift_id, source, approved_by/at, override_reason, note)`; function `attendance_recompute(p_from,p_to,p_employee null)` derives days from punches + roster + leave + holidays (first punch = in, last = out, ignore double punches within N minutes, configurable), never overwrites a manually approved override. Manual entry / correction by manager (location-scoped) with reason, audit-logged.
3. **Leave**: leave types (paid/unpaid, from phase41 entitlements), `leave_requests(employee_id, type, from, to, days, reason, status pending|approved|rejected|cancelled, decided_by, ...)` maker!=approver (owner exempt only while rule owner_self_approve ON), balances per year computed, approved leave marks attendance days as leave (paid/unpaid).
4. **Payroll** `payroll_runs(id, month date(first day), location_id null, status draft|approved|paid|void, created_by, approved_by, notes)` + `payroll_lines(run_id, employee_id, basic, allowances jsonb, days_in_month, paid_days, absent_days, unpaid_leave_days, late_count, late_deduction, ot_minutes, ot_amount, bonus jsonb [{name, amount}], advance_recovery, other_deductions jsonb, gross, deductions, net, calc_detail jsonb, payment_status)`. **DRY RUN first**: `payroll_preview(month, location)` returns every employee's line with the full calculation trail and warnings (missing pay structure, unapproved attendance days, negative net), writes nothing. `payroll_create(month, loc)` makes the draft run (editable lines: add bonus / deduction / adjust with reason), `payroll_approve(run)` (owner) locks the month, `payroll_pay(run, mode, ...)` records payments (cash/bank/mobile) per line. Rules (all editable in rules/Switchboard with sensible defaults): late policy (N late arrivals = 1 day cut; or per-minute cut), absent day cut = basic/days_in_month, paid weekly off & holidays, OT multiples (1.5 normal / 2.0 holiday / weekly off), OT needs approval above X hours, attendance bonus (no absent/late -> amount), festival bonus per phase41 bonus_rules, advance recovery from staff advances (form 35-1 data in entries: expose outstanding advance per employee name/staff id if matchable; otherwise a manual advance table `employee_advances(employee_id, date, amount, recovered, note)` with instalments), final settlement helper (resigned mid-month: prorate). Rounding rules (nearest 1 taka). All figures numeric(…,2).
5. **Salary privacy**: payroll tables + functions: owner or grant `salary_view` / `payroll_manage` only; attendance (not money) visible to managers of that location.
6. **Day book**: salary payments must appear in the day book (typ 'salary', sensitive=true like 21-1 salary lines): re-create `public._daybook_lines23(int[], date, date)` from supabase/phase23.sql adding a union for payroll payments (copy the function text exactly and add your union; keep its columns and `internal=false`).
7. **Fingerprint integration** (devices cannot reach the database directly, and the sandbox cannot reach Supabase - build the pieces that work with real devices):
   * `attendance_devices(id, name, location_id, vendor zkteco|hikvision|suprema|other, serial, token_hash, active, last_seen)`; the owner registers a device and gets a one-time token (store only a hash).
   * **Push API**: `attendance_punch_push(p_token text, p_rows jsonb)` SECURITY DEFINER callable by `anon` (the device bridge uses the anon key) ONLY inserts punches for that device (validates token hash, row count <= 500, timestamps sane, idempotent by the unique key, maps device_user_id -> employee via employees.device_user_id, unknown ids stored with employee_id null and listed in an "unmapped" screen). It must never read anything else. Rate limit per token per minute.
   * **File import** in the app: upload/paste the device export (ZKTeco USB `.dat`/`.txt`/CSV: columns user id, datetime, verify mode, in/out, workcode; also generic CSV with column mapping UI), preview (dry run: counts, duplicates, unmapped ids, date range), then import in a batch (`import_batch` id), undo by voiding a batch (flag, not delete).
   * `tools/fingerprint_bridge.py` (stdlib only + optional `pyzk`): reads punches from a ZKTeco device over the LAN (pyzk) or from an exported file and pushes them in batches to the RPC with the token (config via env: SUPABASE_URL, SUPABASE_ANON_KEY, DEVICE_TOKEN); includes a `--dry-run`, retries, local checkpoint file so nothing is sent twice. Document in docs/FINGERPRINT.md (supported devices, how to get the export, how to run the bridge on a PC / Raspberry Pi as a scheduled task, security notes). Test the bridge against a tiny local fake HTTP server in a Python unittest.
8. **Web**: `#/attendance` (today board per location: present/absent/late/on leave with times, manual mark, approve overrides, date picker, month grid per employee, color chips, unmapped punches, device list/import), `#/leave` (requests + approvals + balances), `#/payroll` (month picker, Preview (trial) -> Create run -> adjust -> Approve -> Pay, payslip view/print per employee, month summary by location, CSV export). Bangla-first. Staff mobile punching from the app is NOT required (optional simple "check in / out" button for staff with a login, switch `app_punch_on` default OFF, location from the user's location, records source app).
