Phase file: supabase/phase40.sql (+ phase40_test.sql). Web: web/accounts.js (+ tests/web/accounts_test.js). Regs: docs/regs/accounts.md. DB names a40*.
Read docs/briefs/00_RULES.md first. Use proper double-entry accounting practice; if you have the Skill tool, invoke the `finance:financial-statements` and `finance:journal-entry` skills once for guidance (do not spend long on it).
Owner's words: "Build the system - Balance Sheet - Ledger, use accounting skill".
## What to build
1. **Chart of accounts** `coa_accounts(id, code unique immutable, name_bn, name_en, type asset|liability|equity|income|expense, parent_id, normal_side debit|credit, is_system, active, sort)`. Seed a sensible bakery/sweets-shop chart (cash in hand, bank, mobile wallets, card receivable, customer receivables, advances to staff, inventory: finished goods / raw materials / packaging, prepaid, fixed assets + accumulated depreciation, supplier payables, accrued salaries, customer advances (liability), owner capital, partner/investor capital, owner drawings, retained earnings; income: sales (by brand optional via dimension), sales returns & discounts (contra), other income; expense: COGS, wastage loss, salaries, rent, utilities, marketing, repairs, transport, cash short/over, bank charges, depreciation, other). Owner can add accounts (never delete; retire).
2. **Journal** `journal_entries(id, entry_date, location_id null, source_type, source_id text, memo, status posted|void, reverses_id, created_by, created_at, client_id)` + `journal_lines(entry_id, line_no, account_id, debit, credit, location_id, party_type customer|supplier|staff|partner|null, party_id text, memo)`. Rules: sum(debit)=sum(credit) (> 0), each line debit XOR credit, immutable (append-only; correction = reversing entry), period lock respected (public.lock_check), `accounting_start_date` rule: nothing before it is posted.
3. **Posting from the business events, WITHOUT touching the hot paths**: a function `acct_post_pending(p_dry boolean default false)` (owner or grant accounts_manage) that scans the source tables for rows that have no journal entry yet (idempotent by (source_type, source_id)) and posts them: sales (cash/mobile/card/receivable split via sale_payments, discount, revenue, and COGS vs inventory only when item cost is known - never invent costs), sale returns, sale voids (reversal), customer collections, purchase bills / returns / supplier payments / supplier refunds, 10-2 expense vouchers (approved), cash_moves (phase23: bank deposit/withdraw, owner top-up/draw, customer advances, hub receipt), wastage, staff advances and salary payments if tables exist (phase 41/42 may not exist: guard with to_regclass). Mapping of payment mode -> account configurable in table `acct_mappings(key, account_id)` (e.g. cash_mode_cash -> Cash in hand). Provide `acct_post_pending(true)` DRY RUN returning counts and the journal it would write (trial calculation shown to the owner before real posting). A screen button "Post now" + automatic call when the accounting screen opens (switch `accounting_autopost`).
4. **Reports** (functions returning jsonb, access: owner or grants `accounts_view` / `accounts_manage`; location filter by can_loc): trial_balance(from,to), ledger(account, from, to) with running balance and links to the source document, journal_book(from,to), income_statement(from,to,loc), balance_sheet(as_of, loc) (retained earnings = cumulative income - expense; must balance: assets = liabilities + equity, else return a `unbalanced` flag with the difference), cash_flow_simple(from,to), party_ledger(party_type, party_id) for customers/suppliers (sub-ledgers must agree with existing customer_dues() / supplier_dues() - add a reconciliation function returning differences).
5. **Manual journal** for the accountant/owner: balanced-entry form with validation, memo, attachments optional (photo path), idempotent client id; opening balances wizard (one dated opening journal; refuses if postings exist before it).
6. **Web** `#/accounts` (tabs via select/segmented: Overview with the balance-sheet and P&L summary + "Post now" + unbalanced warnings, Trial balance, Ledger (pick account, date range, running balance), Journal, Chart of accounts (add/rename/retire), New journal, Opening balances, Settings (mappings)). Printable (print stylesheet like web/invoice.js or daybook print) and CSV export for each report. Bangla-first labels.
## Security / honesty
Costs: COGS lines only when item costs exist (item_costs / stock_ledger unit_cost); otherwise post revenue only and flag `cogs_missing` count in the overview - never guess. Reports must say "Data needed" when accounting_start_date is unset. Everything switchable: rules `accounting_on` (default OFF until the owner sets the start date and opening balances), `accounting_autopost`, `accounting_start_date`.
## Tests
Concrete numbers: post a few sales/purchases/expenses in the test DB, assert the trial balance equals expected, balance sheet balances, reversal on void, idempotent re-post (second run posts 0), dry-run writes nothing, period lock, permission checks, location scoping, immutability.
