## What to build
1. **Home cleanup (nav.js)**: remove the "Recent" block from Home (both v2 and old layouts; keep the data function if other code uses it, but do not render it). Remove every ☆/★ star button from tiles, rows, drawer entries and the page header; favouriting is done ONLY from a ⋮ (three-dot) menu on each tile / drawer row / header (keep the same storage and the cross-device sync that favsync_test covers; update that test for the new UI). The ⋮ menu (use the existing collapsed-control menu `B.ctl.menu` if it fits, else a sheet with `data-ctl` kit style) offers: Add to / Remove from favourites, Move up, Move down, Move to top, Move to bottom (reorders the user's favourites), Rename label (per user), Hide from Home, Open, Copy link, Reset order. Favourites order must persist per user and sync like before. Provide the same actions on the Favourites section when in "edit" mode. Keep all tests that count tiles/stars in sync.
2. **Owner Mode board** `#/owner` (owner only; also reachable from a prominent button on the owner's Home - an "Owner mode" tile/button next to "Sell", and a toggle "Owner mode" in the header ⋮ that makes Home show the board). The board is a list/grid of **widgets** the owner can customise:
   * Catalog of widget kinds (data-driven, in one JS object; each = key, label bn/en, group, loader function returning {value, tone ok|warn|bad|info, sub, route}) built ONLY from data that already exists: today's sales vs yesterday / same weekday last week (sales_summary), cash short/over today (14-1/10-1 flags or cash_short_over), open exceptions red/yellow, Needs you (needs_you_oldest), pending approvals, low stock count + expiring soon (stock functions used by nav.js counts `cn.low`), customer dues total and overdue, supplier dues, day-close status per shop (06-1 submitted today), unsent offline forms, wastage today, voided sales today, discounts given today, top sellers today, parallel-month decisions waiting, rollout board (forms still on paper), backups status (read table `backup_runs` if it exists - guard), unread notifications count (table `notifications` if exists), attendance today (table `attendance_days` if exists), payroll due, accounts balance sheet check (function `balance_sheet` if exists), and a generic **"Report shortcut"** widget (pick any report from the report catalog, shows its headline total), **"Page shortcut"** (any registered route from B.IA), **"Counter"** for any table with a filter (limited, safe presets), **"Note / reminder"** (free text checklist item the owner ticks daily, resets daily or weekly).
   * Everything missing (module not installed) is hidden from the catalog, never an error.
   * **Customise**: "Edit board" mode: add widget from the catalog (searchable, grouped), remove, reorder (move up / down / top via ⋮ menus and drag handles are optional), rename, set thresholds / tone rules (e.g. warn when value > N), choose size (compact / wide), enable/disable, reset to default set. Per-user storage `owner_board_items(id, user_id, widget, config jsonb, sort int, enabled bool, updated_at)` with RLS (own rows; owner only) and RPC `owner_board_save(items jsonb)` replacing the user's list atomically (validated widget keys; max 60 items) + `owner_board_get()`. If the table is missing the board falls back to the built-in defaults in localStorage.
   * **Defaults** (a sensible owner morning routine, in this order): Today's sales vs yesterday, Cash short/over, Day close status of every shop, Needs you (oldest first), Open red exceptions, Pending approvals, Customer dues, Supplier dues, Low stock + expiring soon, Wastage today, Voids + discounts today, Unsent forms, Backup status / notifications (when installed), plus "Daily checklist" notes: check cash counts, check stock counts, review exceptions. All removable.
   * Each widget tap opens the relevant page. Pull-to-refresh button; auto refresh every 2 minutes while open (light queries, one batched load). Works offline gracefully (shows last values with an "as of" time).
3. Settings/rules: `owner_board_on` (default ON), `home_recent_off` n/a (recent removed). Register routes in ia.js yourself (`owner`, group 'settings' or home) and the script tag in index.html.
