# Module D: Partnership / investment / profit-sharing / franchise - a flexible DEED (agreement) engine
Phase file: supabase/phase44.sql (+ phase44_test.sql). Web: web/partners.js (+ tests/web/partners_test.js). Regs: docs/regs/partners.md. DB names a44*. Owner-only (sensitive).
Read docs/briefs/00_RULES.md first. Background: docs/inputs/Build-commands-functions-only.md mentions location models A (own) / B (franchise) / C (funded) that were left as placeholders; locations.model exists (phase16).
Owner's words: "I can make anything - any rules - amount - investment - profit - customize the deed - profit sharing - partnership - anything needed for this system."
## What to build (a rule ENGINE, not fixed templates)
1. **Parties** `partner_parties(id, name, kind individual|company, mobile, email, nid_or_reg, address, photo_path, notes, active)`.
2. **Ventures** `partner_ventures(id, name_bn/en, scope location|business|product_line|custom, location_id null, model own|franchise|funded|partnership|loan|custom, start_date, end_date null, status draft|active|closed, notes)`.
3. **Agreements (deeds)** `partner_agreements(id, venture_id, title, version, status draft|active|amended|closed, effective_from, effective_to null, clauses jsonb [{no, title_bn/en, text_bn/en}] (free, editable, reorderable), signed_doc_path, supersedes_id, created_by, created_at)`: immutable once active (amendment = new revision linked by supersedes_id; old stays readable). `agreement_parties(agreement_id, party_id, role owner|partner|investor|franchisee|manager|lender, share_percent null, notes)`.
4. **Capital & investment** `partner_capital(id, agreement_id, party_id, kind contribution|return_of_capital|loan_in|loan_repayment|owner_drawing, amount, date, mode cash|bank|mobile|in_kind, description, ref, status posted|void)` append-only (void flag), running capital balance per party, outstanding payback.
5. **Profit-sharing rule engine**: `partner_rules(agreement_id, step_no, name, kind, config jsonb, active)` evaluated in order by `partner_calculate(agreement, from, to, p_manual_base jsonb default null)` which returns the full waterfall WITHOUT writing (trial calculation). Steps are generic and combinable: `base` selection (gross_sales | net_sales | gross_profit | net_profit_before_fees | net_profit | fixed_amount | manual), `royalty` (percent of a base to a party), `management_fee` (percent or fixed), `expense_allow/disallow` lists, `loss_carry_forward` (carry negative periods), `priority_return` (e.g. investor first gets X% of capital per year or a fixed monthly return until paid, with cap and optional catch-up), `payback` (all profit to investor until capital recovered, then switch), `split` (percentages among parties; must sum to 100), `tiered_split` (slabs: first N at a%, next M at b%, above at c%), `minimum_guarantee`, `cap`, `floor`, `rounding`. Config validated by `partner_rule_validate(kind, config)`. Bases come from the books: net/gross sales (sales net of returns), gross profit (sales - costed COGS via the same logic as supabase/phase23.sql biz_daily), expenses (11-1 via the extraction used in supabase/phase25.sql / phase27.sql `_p27_pl`, read it), or - if module A (supabase/phase40.sql, may not exist yet) is present - journal balances (guard with to_regclass). If a base cannot be computed honestly return null + a warning and let the owner type a manual base; never invent numbers.
6. **Settlements** `partner_settlements(id, agreement_id, period_from, period_to, status draft|approved|paid|void, calc jsonb (the full waterfall as computed), total_distributable, approved_by/at, note)` + `partner_settlement_lines(settlement_id, party_id, amount, kind share|royalty|fee|return|payback, paid_amount, paid_at, pay_mode)`. Flow: preview (trial) -> save draft (snapshot of the calc, never recomputed silently) -> owner approves -> payments recorded (cash/bank/mobile; creates a cash_moves-style outflow? only record in the settlement tables and expose lines for module A to post later) -> party statement. Overlapping periods per agreement refused. `partner_party_statement(party, from, to)` = capital in/out + shares due + paid + balance owed, printable.
7. **Web** `#/partners` (owner): Overview (ventures with status, capital totals, next settlement due, balances owed), Parties, Ventures, Agreement editor (clause editor: add/edit/reorder/remove clauses; party roles and shares; rule builder: add step -> pick kind -> form fields from a catalog describing each kind's config; live JSON-free friendly summary sentence like "Investor gets 30% of net profit until 500,000 paid back, then 20%"), Trial calculation screen (pick period -> shows the waterfall step by step with amounts; manual base override), Settlements (draft/approve/pay), Capital ledger, Party statement + print. Templates for common deals seeded as examples the owner can copy and edit (franchise: royalty 5% of net sales + monthly fee; investor payback; 50/50 partnership; fixed-return loan) - clearly marked EXAMPLE, inactive, no numbers presented as policy.
8. Switch `partners_module_on` default ON (owner-only screens anyway). Everything auditable.
