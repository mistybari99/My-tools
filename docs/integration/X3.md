## 4. What the owner links later

1. **Facebook Page**: a Meta developer app; the Page added to it; a Page access token from a person who is an admin of the Page. Permissions for posting (`pages_manage_posts`, `pages_read_engagement`, `pages_show_list`). Several of these need Meta App Review and business verification before they work for pages other than your own admins. The shapes in the adapter follow the Graph API version pinned in `tools/social_publish.py` (v19.0); check the current changelog first.
2. **Instagram**: an Instagram professional account linked to the Page; its user id; the `instagram_business_content_publish` permission (App Review). Instagram publishing needs public media URLs.
3. **WhatsApp Business**: a WhatsApp Business account; a phone number id; a system-user token with messaging permission; the message templates approved by Meta in the language you use (`SOCIAL_WA_LANG`, the exact language code of the approved template). Free text is not used at all.
4. **Generic webhook** (optional): an https address and a bearer token from the receiving service.
5. **GitHub**: secrets `SOCIAL_FB_PAGE_ID`, `SOCIAL_FB_PAGE_TOKEN`, `SOCIAL_IG_USER_ID`, `SOCIAL_IG_TOKEN` (optional), `SOCIAL_WA_PHONE_NUMBER_ID`, `SOCIAL_WA_TOKEN`, `SOCIAL_WEBHOOK_URL`, `SOCIAL_WEBHOOK_TOKEN`; variables `SOCIAL_WA_LANG`, `SOCIAL_MEDIA_BASE_URL`, `SOCIAL_SEND_ENABLED` = 1 only when ready. The bot login (`NOTIFY_BOT_EMAIL`, `NOTIFY_BOT_PASSWORD`) is the existing one.
6. **First test**: a dry run from the Actions tab; then one text post to a test Page with `send` ticked and the switches on; check the Page and the item trail in the app.

Never paste a token into chat, a file or the database. Rotate it if it was shown.

## 5. Untested and open

* The adapters have never talked to Meta or WhatsApp. Every request shape is UNVERIFIED until one live test post. A changed response field will show as `provider gave no post id`.
* `social_media_image_mb` (5) and `social_media_video_mb` (50) are proposed starting values, marked not verified in the info file; the owner confirms them.
* `social_retry_max` defaults to 5 tries, the same as the SMS queue.
* No real volume test: the limits and back-off are tested with a few rows only.
* The parser is rule-based. Its accuracy on real chats is unmeasured; every suggestion is shown with its confidence and a person saves the order.
* The SQL before/after snapshot of existing reports (defaults parity) was not run for phase 483. The phase adds tables, rules, grants and functions only and changes no existing function, but this was not measured.
