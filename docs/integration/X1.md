# Integration note X1: the shared foundation (phases 479 and 480)

Owner intent: every system (website, social, AI agents, automation) is built now, nothing needs a domain, hosting or account today, and the day the owner has one he only LINKS it from the Connect Center. This package is the shared base the other packages call. Local throwaway Postgres only; the live Supabase project was not touched; nothing pushed.

## 3. Names the other packages must call

Gate (every outside or AI call; deny reasons: `automation_off`, `paused`, `unknown_integration`, `integration_off`, `not_configured`, `read_only`, `do_not_contact`, `budget_not_set`, `budget_exhausted`, `rate_limited`, `dry_run`):
`select x1_gate('<kind>', '<connection code>', <is_write>, <customer uuid or null>)` returns `{allow, reason, dry_run}`. A write is never allowed while `dry_run` is ON.

Connection codes (seeded): `website`, `hosting`, `facebook_page`, `instagram`, `whatsapp_business`, `sms_gateway`, `email_smtp`, `bkash`, `nagad`, `ai_provider`, `vision_provider`, `analytics`, `other`.

Site config for X2: `site_config_get()` (signed-in users only; anon is refused, see section 5).

Proposals (agents and jobs): `action_propose(client_uuid, target_rpc, args jsonb, reason, hours)`; the owner decides with `action_decide(id, 'approve'|'reject', reason)`; the owner's session runs the target and calls `action_proposal_mark_executed(id, ok, result)`. A target must be enabled by the owner with `action_target_set`. Rules, grants, audit, money and journal names are refused as targets (trigger).

Jobs: `job_run_start(job, dry)` -> `{allowed, reason, run_id, dry_run}`, `job_run_finish(run_id, ok, error, counts)`, `job_heartbeat(job, note)`. Jobs: `notify_sms`, `intake_retry`, `heartbeat` (the wrapper), and the expected list in health: `notify_digest`, `notify_sms`, `intake_retry`, `kb_rebuild`, `backup`.

## 4. Safety properties (tested)

- anon: no read of any X1 table, no execute of any X1 function (phase479_test T2, T12; phase480_test T3, T10).
- staff without owner or bot or agent: refused by the gate, the job functions, the registry (empty to them), the health view.
- secrets: no column named like a secret in any X1 table; no function parameter named like a secret; config refuses secret-looking keys and values; env_names refuse values; the backup whitelist still includes the X1 tables (phase479_test T6).
- agent accounts: cannot receive a role or any grant (triggers, including `set_rule`, grant rights, audit view, accounts posting); an owner cannot make a person with roles into an agent; agent calls to rules and grants are refused (phase479_test T8).
- kill switch: `automation_on` OFF or a pause in force: the gate denies everything, `job_run_start` records a skipped run that counts as neither ok nor failed (phase479_test T4, T5, T7; phase480_test T8).
- do-not-contact: wins over an allowed read (phase479_test T5).
- nothing is deleted from any X1 table (no_hard_delete trigger; phase479_test T3, phase480_test T9).
- paste twice: phase479 and phase480 pasted twice clean (phase479_test T12, phase480_test T10).

## 5. Not built, not verified, open decisions

- **Not deployed:** `tools/edge/x1-connect-check.ts` (Test connection) is source only. Until deployed the button shows "not available yet"; no connection can become `connected`.
- **Not run against a real project:** no live Supabase, no real phone, no real GitHub Actions run (the workflow file is syntax-reviewed only). The `intake_retry_due` call needs the ops bot to be registered in `intake_bots` (phase76) before a live run works.
- **Existing jobs not yet hooked to `job_runs`:** deliberate (section 2). Owner must decide whether these jobs are recorded and gated (this turns OFF `automation_on` into a stop for the existing alerts) or only recorded.
- **Public website read:** `site_config_get()` is signed-in only. The website (X2) needs anon read of the public fields: that is a decision for the owner (a view with only public fields is the likely design); not decided here.
- **Per-provider cost counters:** not a separate table. The gate log counts calls per connection per month (`x1_gate_log`). Token and money counters are not built (money is out of scope for this package).
- **Rate limiting:** only the per-minute count inside the gate; no separate rate-limit table.
- **Outbound webhook delivery log:** not built (the gate log covers calls; add later if X3 needs it).
- **Agent sign-in:** the account rows and their limits are tested in SQL. The sign-in itself (anon-key login) is not tested.
- **Action list is empty:** nothing can be proposed until the owner allows a target.
- **Local database encoding:** the throwaway cluster is SQL_ASCII, so `phase15.sql` logs one conversion error during the build (environment only; the same error happens with and without X1).
- **Minutes budget:** `automation.yml` runs every 30 minutes (as asked). Together with `notify.yml` this is about 2,170 Actions minutes a month against 2,000 free. The file header gives the one-line change to every 2 hours.
