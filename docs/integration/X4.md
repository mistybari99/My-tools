# X4 (AI helpers): integration with X1 and what is stubbed

X1 (branch x1-foundation, phases 480-489) is not merged yet. X4 does not duplicate its objects. Where X4 needs one, it names it here and writes a TODO adapter. When X1 lands, the adapters are the only place to change.

## Names X4 references (from X1, not built here)
| X1 object | What X4 uses it for | X4 today | Adapter to write when X1 lands |
|---|---|---|---|
| `action_proposals` | where an agent's proposal becomes an approval item | suggestion row with `kind = 'proposal'` in `ai_suggestions` (phase511) | in `ai_suggestion_add`: when kind = 'proposal', also insert into `action_proposals` with `actor_type = 'agent'`, `agent_id = p_agent` (one TODO line marked `X1-ADAPTER`) |
| `_x1_gate` / master switch | the company-wide AI and automation stop | `ai_pause_all` (phase510, owner) | `ai_check` also reads `_x1_gate('automation')` when it exists (`to_regprocedure` check, so the phase is safe without X1) |
| `job_runs` | a record of each scheduled AI run | not written | optional; `ai_calls` is the AI log today |
| `agent_accounts` | each agent as its own login with scoped grants | the agent is a row in `ai_agents` and its grants in `ai_agent_grants` | later; until then agents act only through the signed-in person's session |
| `integration_registry` | the Connect Center row for each provider | the provider row in `ai_providers` (no key) | the Connect Center lists `ai_providers` rows; the key stays in Supabase secrets |

## Rules that do not depend on X1
- Proposals never change data. An approver executes an approved proposal through the existing RPC with the approver's own rights.
- The person who asked never decides their own suggestion (`ai_suggestion_decide`).
- An untrusted-input agent has no proposal action (table check, trigger, RPC check, runtime check).

## How the adapter is tested later
1. Paste `phase510` and `phase511`, then X1's phases.
2. Re-run `tests/sql/phase511_test.sql` (K2 must still pass: proposals stay suggestions until the adapter writes them).
3. Add one test: an approved proposal creates the action only through the existing RPC, and the approver is the actor.
