Master integration of all finished packages onto one branch. Local throwaway Postgres only; the live Supabase project was never touched. Owner paste list: `docs/PASTE_ORDER.md`.

w1-check-fixes-2 (phases 140-143), INFO-1, R1 (120), R2 (130-132), CRM A, B, C, F, G, H (300-329), RPT-B1, B2, B3, B4, C1, C2, C3 (400-468), RPT-HUB (renumbered, 470-476), the UI inventory safety net (docs and test tooling only) and `docs/ARCHITECTURE_DESIGN.md`. ## 3. Phase 477 "repatch all"

`supabase/phase477.sql` (generated by `python3 tools/build_phase477.py`, `--check` verifies it) re-applies every exact-text hook of the packages after any old phase was pasted again: RPT-B1 (13), RPT-B3 post_purchase, CRM-B (2), CRM-C notify_scan, C1 (7). It also holds the glue:

- bos477: the f3 raw-vs-recipe check counts an RPT-B4 real-use record as a measurement.
- bos477b: drops the old 4-argument `qc_list` when the 6-argument one exists.
- bos477c: either privacy switch (CRM-A `crm_mask_phone`, CRM-B `crm_pii_guard_on`) hides numbers on both families of screens. Both OFF = nothing hidden.
- Exceptions kinds from R1 and CRM-G (r1_unbacked_payment, crmg_late_quote, crmg_lead_reopen, crmg_win_without_quote) are merged by a helper, not by editing old phases.

Whole-function re-creations are not restored by 477. They need the named phase pasted again (420: report_run2, report_catalog2, stock_reconcile, p4; 421: k2; 432: qc_list/qc_record; 434: p2_rate_trend; 441: x4), and then everything from that phase up to 98 in order, then 477. `select * from _i2_state()` lists what is missing. `supabase/phase477_test.sql` (33 checks) proves it.

## 4. Decisions inside the merge

- Yield screen: the RPT-B4 Yield tab (`#/prodreports/yield`) is the one screen; the RPT-B3 Yield tab in stock shows a card linking to it. The SQL `yield_report` stays.
- Reports hub and reports map are both live and cross-linked (`#/reports/hub`, `#/reports/map`). The map fills sections 5-14 from `web/data/report_registry.json` (193 reports: 170 implemented, 20 incomplete, 2 unverified, 1 unavailable).
- CRM-A directory/phone/WhatsApp hooks are superseded by CRM-B's. CRM-A's Customer 360 and "More profile details" open only while `crm_on` is ON; at the default the old profile sheet opens.
- Package hooks applied by script: nav.js (pay-request count, CRM tasks strip, 11 CRM grant codes), notify_digest.py (CRM-G task scan, CRM-H SLA scan), customers.js, pos.js, inbox.js, index.html, ia.js, info.json merges (437 entries), the (i) sign (`data-info` on screen titles and switchboard rows).
- R2's `data-info` on body containers was removed: `.ihint-host` is inline-flex and made three screens overflow.
- Handler-name clashes (last handler wins in the shared `H` object) were renamed: crm_segments cs_ to crs_, purchrep pr_ to pur_, trace rc_ to trc_, crm_coupons cp_ to cpn_, capacity cp to cap_. Without this the costing, payroll, recipes, otherincome, customers and campaigns screens hung.
- UI inventory baseline gets new items only (`--update-baseline` never drops); 4 aliases for renamed RPC calls / button.
- `tools/demo_leak_test_baseline.json` has one entry for `tests/ui_inventory/baseline.json` (3), caused by "rahim01" that already was in `web/i18n.js`. App text not touched.
