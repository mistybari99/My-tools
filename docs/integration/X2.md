## 2. Hook sites (existing objects touched)

Only these; no existing function was replaced or edited.
1. New column `online_orders.web_code` (phase482, unique when set).
2. New trigger `online_orders_holds91` (AFTER UPDATE OF status) on `online_orders`: releases holds on cancel, consumes them on delivery. It writes only the new hold table.
3. New rows in `rules` (phase481, `on conflict do nothing`).
4. `web/ia.js`: one `rec('website', 'sale', ...)` line. `web/index.html`: one script tag after `inbox.js`.
5. Storage policies on `storage.objects` for buckets `web-refs` and `web-public` (only where the storage schema exists).
No existing phase file was edited. Existing order functions (phase 61, 76, 77) are untouched and the existing online order screens still work (test T10).

## 4. Not built (honest list)

- Customer accounts-lite and phone OTP (SMS adapter stub): NOT built. Saved addresses, reorder and loyalty view: NOT built.
- Coupon validation on the public site: NOT built. The customer's coupon code is written into the order note for staff to apply with the existing coupon screens (`crmf_coupon_*`). A public coupon check needs a customer context; that is a later step.
- Online payment gateway: NOT built (adapter interface only in the plan). Payments are COD or manual bKash/Nagad with a Trx ID.
- Captcha provider: NOT connected. With `website_captcha_on` on, the shop refuses orders.
- Outbound price and stock sync to any other shop: NOT built, by design. The drift report only compares the published snapshot with the ERP. No loop is possible because nothing is pushed.
- Festival pre-order is a flag and lead days; no ingredient pre-purchase list.
- Loyalty points on the site: NOT built.
- Facebook Pixel and Google Analytics: only the ID settings and the consent-gated loader; no real ID set, nothing sent.
- Multiple branches: pickup points and the receiving branch work; per-branch catalogue stock is the branch's own stock.
