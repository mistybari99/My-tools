# UI inventory (no-loss safety net)

`baseline.json` is generated by `python3 tools/build_ui_inventory.py` and committed. `tools/check_ui_inventory.py` compares the current tree with it. Rules and process: `docs/UI_NO_LOSS_RULE.md`. Do not edit `baseline.json` by hand except to retire an item on purpose (reviewed commit with a reason). `aliases.json` lists intended renames.

## File format
```
{ "version": 1, "note": "...", "unparsed": [ "things the extractor could not read", ... ],
  "items": [ { item }, { item }, ... ] }       // one item per line, sorted by id, stable between runs
```
Item fields:

| field | meaning |
|---|---|
| `id` | stable identity, `<prefix>:...` (see below) |
| `kind` | route, qa, group, do, page, text, keyword, placement, form, section, note, field, option, setting, button, tab, link, action, input, textarea, select, ctl_option, rpc |
| `level` | `must` = losing or renaming it fails the check; `info` = reported as a note |
| `conf` | `high` = read from the real registries or plain text; `medium` = label or key partly computed, or options depend on live data |
| `source` | file the item comes from |
| `labels` | `{bn, en, mix}` texts of named things (routes, forms, fields, options, settings). A changed text counts as a rename |
| `texts` | visible texts of a control. `L:bn\|en\|mix` is a resolved text key, `{...}` marks a computed part, `t:key` an unresolved key |
| `attrs` | other facts (group, drawer, status, type, required/condition source, ...), informational except the route placement rules below |

## Id prefixes
| id | what |
|---|---|
| `route:<route>` | route in `web/ia.js` (labels, group, status, drawer, mob/mod/home/cc/cnt placement, persona permission source in `attrs.ok`) |
| `qa:<route>:<target>` | quick action of a route; `do:<id>` "Do" action; `group:<id>` category; `page:<name>` registered screen; `text:<key>` i18n text |
| `kw:<route>:<word>` | search keyword (info); `place:quick/slot/home/area:...` persona, bottom bar and Home placement (info) |
| `form:<code>` | paper form (name bn/en/mix from the seed SQL, `spec_bn/spec_en` from the code) |
| `field:<code>:<key>` | form field; table columns are `<table>.<column>`; `attrs` has type, `req`, `show` (conditions) |
| `option:<code>:<field>:<value>` | form option; `option:list:<list>:<value>` option-list seed; `option:rule:<key>:<value>` rule choice |
| `section:<code>:<slug>`, `note:<code>:<hash>` | form section title and form note (info) |
| `setting:rule:<key>`, `setting:grant:<code>`, `setting:loc:<key>` | rules, grants and location settings with labels |
| `ctl:<file>:<kind>:<key>` | button / tab / link / action / input / textarea / select of a screen file; key is `data-act` (plus `#data-v`), id, name or the label |
| `ctl:<file>:option:<select key>:<value>` | static `<option>` of a select |
| `rpc:<file>:<name>` | RPC name called from a screen file |

## Route placement rule
For a `route:` item, a baseline `status: live` that is no longer live, or `drawer: true` that is no longer true, fails (menu entry no longer reachable) unless a `placement` alias exists. Other placement changes (group, mob, mod, home, cc) are notes.

## How it is produced
1. `tools/ui_inventory_runtime.js` (node, no packages) loads `web/*.js` in the order of `web/index.html` inside a sandbox with a ghost DOM and prints the registries the scripts build: `BOS.IA`, `BOS.forms`, `BOS.SETTING_DEFS`, i18n texts, registered pages.
2. `tools/build_ui_inventory.py` parses `supabase/schema.sql` and `supabase/phase*.sql` (no `_test`, no `ALL_NEW*`) for `forms`, `rules`, `grant_defs` and `option_lists` seeds (INSERT ... VALUES, INSERT ... SELECT from literals or `(values ...)`, and the plpgsql loop form), and scans the HTML inside the JS files for controls. Comments are stripped; texts of the form `T('key')` are resolved through each file's own text table, then through `web/i18n.js`.
3. Output is deterministic (sorted, no timestamps), so two runs on the same tree give byte-identical files.

`unparsed` lists what could not be read statically (inputs with no id/name/label, options that depend on live data, scripts not referenced by `index.html`, seeds filled from other tables).
